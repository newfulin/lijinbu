## 2. 设计硬约束（Cursor 必须遵守）

### 2.1 Token

| Token | 值 |
|-------|-----|
| 主色 Primary | `#0D9488`（teal） |
| 页面底 | `#F7F8FA` |
| 卡片 | `#FFFFFF`，圆角 **12px**，轻阴影 |
| 收入 / 收礼 | 软绿（文字与 pill） |
| 支出 / 送礼 | 软红 |
| 间距网格 | **8px** 倍数 |
| 字色 | 深灰正文 / 次级灰说明 |
| 图标 | 细线 stroke，现代 SaaS |

### 2.2 布局铁律

- **左导航 + 顶栏**；顶栏主 CTA「记一笔」永远最醒目（主色实心按钮 + 加号）。
- 往来页：中区大白卡表格 + **右侧三张摘要卡**（本月 / 今年 / 概览），对齐 `style-01`。
- 联系人页：对齐 `style-02` 信息密度与卡片样式；提醒可独立页或右栏，见 F05/F07。
- **统计页**为左栏独立页（F13），视觉仍服从 token，勿炫技。
- 窗体最小 **1100×720**；默认建议 1280×800。
- Win / Mac **同一套 UI**；仅系统窗口控制按钮随平台。
- **关怀模式**开启时：基础字号与行高放大一档，表格可滚动优先，不挤扁。

### 2.3 禁止

- 卡通猫、浓渐变、花哨插画抢数据区
- 拥挤表格、过小行高、无千分位金额
- 居中大 Modal 记一笔
- 常驻全屏 / 全页 WebGL·Three.js 壳；用 Three.js 画统计图
- 核心构建强制捆绑 `three`（仅实验开关开启时再加载）
- 红/白事主题换肤（延期）

### 2.4 对照图使用方式

开发每个页面前打开对应 jpg：色、圆角、侧栏宽度感、表格列、pill、头像字、分页与空态气质必须一致。差异以「更干净、更留白」为方向，不得更花。统计页无专用 jpg 时：沿用 style-01 的卡片与摘要气质。

### 2.5 动效规范（锁定）

**默认（所有用户）**

- 技术：CSS 与/或 Canvas 2D；**不**加载 Three.js。
- 记一笔保存成功：
  - 收礼：浅绿脉冲 + 「+¥金额」轻量飞入/飘字
  - 送礼：浅红脉冲 + 「−¥金额」轻量飞入/飘字
- 单次动效时长建议 ≤ 600ms（脉冲）/ 飞入可至 ~800ms。
- 设置：**「减少动效」** 开关；开启后仅瞬时反馈（toast / 列表插入），无脉冲与飞入。
- 系统 `prefers-reduced-motion: reduce` 时等同「减少动效」开启（可与设置联动）。

**实验性 3D（可选，默认关）**

- 设置文案建议：「实验性 3D 微缩庆祝（保存成功时短时动画，可能略增耗电）」。
- **仅**在「记一笔」保存成功且开关 ON、且未开「减少动效」、且无 reduced-motion 时触发。
- 内容：**纯代码**生成案头 + 礼簿微缩场景；时长 **1–1.5s** overlay，然后销毁 WebGL 上下文。
- **禁止**：glTF / 外部贴图包 / HDR / 常驻背景 / 列表与统计页 WebGL。
- 实现：`await import('three')`（或等价动态加载）；失败则静默回退 CSS/2D。
- 核心 CI / 默认 release：**可不打包 three**；文档注明开启实验项后首次可能下载或加载可选 chunk。

## 4. 技术栈建议（G0）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **Tauri + SQLite（默认推荐）** | 安装包小、内存低、原生感好 | 前端需 Web 技术栈；Rust 侧学习成本略高 |
| Electron + SQLite | 生态熟、调试易 | 包体大、占内存 |

**默认选型：Tauri 2 + 前端（React/Vue/Svelte 任选其一）+ SQLite。**  
图表：Recharts 或 ECharts（2D）。拼音：`pinyin-pro` 等轻量库，写入/更新联系人时维护检索字段。  
用户若坚持 Electron，允许切换，但 IA / UI / 验收不变。

**G0 验收**

- [ ] 空壳可在 Win 与 Mac 启动
- [ ] 左导航可切换占位页（含「统计」占位）
- [ ] SQLite 文件落在用户数据目录；路径在设置中可「打开目录」
- [ ] 账本级：推荐 **一库 + book_id** 便于备份
- [ ] 默认产物 **不含** 强制 three 运行时（或 three 仅在可选 chunk）

## 5. 数据模型草图

```text
books
  id, name, created_at, updated_at, is_archived

members                    -- 家庭成员标签（谁出的礼）
  id, book_id, name, sort, is_default, created_at

contacts
  id, book_id, name,
  name_pinyin,             -- 全拼小写，检索用（F15）
  name_initials,           -- 首字母，如 zhangsan → zs（F15）
  relation_tag_id, note, location,
  is_stopped, merged_into_id,
  created_at, updated_at, deleted_at   -- 软删进回收站（F17）

relation_tags              -- 关系标签：亲戚/同事/同学/其他 + 自定义
  id, book_id, name, is_system, sort

transactions
  id, book_id, contact_id, member_id,
  direction enum('in','out'),   -- in=收礼 out=送礼
  amount_cents integer,         -- 整数分，避免浮点
  date_gregorian date,          -- 公历 YYYY-MM-DD
  event_title, festival_tag_id, note,
  payment_method enum('cash','wechat','alipay','bank','other') nullable,  -- F19
  gift_note text nullable,      -- 实物礼品描述 F19
  created_at, updated_at, deleted_at   -- 软删 F17

festival_tags
  id, book_id, name, is_builtin, sort

reminders
  id, book_id, contact_id, transaction_id nullable,
  type enum('fixed_date','after_receive_days','before_festival_days'),
  trigger_date, days_param, amount_hint_cents,
  title, is_important, is_completed, completed_at,
  snooze_until, created_at, deleted_at

contact_settle_marks       -- 「视为已还」标记（不删流水）
  id, book_id, contact_id, marked_at, note,
  baseline_balance_cents    -- 标记时的差额快照（可选）

settings
  key, value_json
  -- 例：pin_hash, lunar_on, reduce_motion, experimental_3d_celebrate,
  --     care_mode_large_text, gift_suggest_on, recycle_retain_days
```

**索引建议**：`transactions(book_id, date_gregorian)`、`transactions(book_id, contact_id)`、`contacts(book_id, name_initials)`、`contacts(book_id, name_pinyin)`、软删查询用 `deleted_at`。

**待还余额计算（锁定）**

```text
balance(contact) =
  SUM(amount where direction=in  and contact and deleted_at is null) −
  SUM(amount where direction=out and contact and deleted_at is null)

待还列表条件：
  balance > 0
  AND 无有效 settle_mark
  （v1 简单实现：标记后隐藏；提供「取消视为已还」；帮助文案说明。）
```

**农历**：存公历；UI 用库（如 `lunar` / `tyme4ts`）展示层换算。

**回礼建议额（F20，可关）**：以当前 `balance` 为基数，向上取近吉利数（如含 6/8/9 的整百/整十策略，实现时定一张小规则表并单测）；仅建议，用户可改；设置 `gift_suggest_on` 默认开。

## 6. 功能模块与验收标准

### F01 账本

**能力**：新建、重命名、切换、删除。

**验收**

- [ ] 侧栏「当前礼簿」下拉展示全部未归档账本；切换后往来/联系人/提醒/统计全部重载
- [ ] 新建：名称必填；seed 默认一本
- [ ] 删除：二次确认；**至少保留 1 本**
- [ ] 数据按 book_id 隔离

---

### F02 成员标签

**能力**：设置中 CRUD；记一笔绑定成员。

**验收**

- [ ] 默认成员「我」，不可删可改名
- [ ] 往来/统计可按成员筛选
- [ ] 删除有关联流水时阻止并提示数量

---

### F03 记一笔（右侧抽屉）★ 核心

**打开方式**：顶栏「记一笔」、⌘/Ctrl+N、空态主按钮。  
**形态**：右侧抽屉 420–480px；遮罩可关；Esc（脏数据确认）。

**字段与 UI**

| 字段 | 规则 |
|------|------|
| 联系人 | 必填；拼音/首字母即时搜（F15）；同名提示（F16）；可新建 |
| 关系标签 | 预设亲戚/同事/同学/其他 + 自定义 |
| 类型 | 收礼 \| 送礼 |
| 金额 | 必填 > 0；千分位；元 |
| 金额快选 | **200 / 500 / 800 / 1000** + 键盘自定义 |
| 日期 | 公历；旁注农历；默认今天 |
| 事由 / 事件 | 文本 |
| 节日/事件标签 | 内置+自定义 |
| 成员 | 默认「我」 |
| 支付方式 | 可选；见 F19 |
| 礼品 | 可选文本；见 F19 |
| 备注 | 可选 |
| 创建还礼提醒 | Switch；开则写 reminders |

**验收**

- [ ] 非 Modal；宽 420–480
- [ ] 快选 chips 可用；农历随日期变
- [ ] 保存 → 写库 → 关抽屉 → 列表更新 + toast
- [ ] 触发 §2.5 默认 2D 动效；若实验 3D 开则叠加短时 overlay 后销毁
- [ ] 「保存并继续」可选：清空金额/事由，保留联系人与类型

---

### F04 往来页

**布局**：对齐 `style-01`。Tab：全部 \| 收礼 \| 送礼。

**表列**：日期（+农历）、类型 pill、联系人、事件、金额、支付方式（可折列）、成员、备注、⋯  
**行操作**：编辑、删除（进回收站 F17；可另保留短时撤销条作为 UX 糖）。

**右栏**：本月 / 今年 / 概览（允许 sparkline）；「查看详情」可跳转统计页。

**验收**

- [ ] Tab/分页/千分位/着色正确
- [ ] 右栏与库一致；空态克制无卡通猫
- [ ] 删除进回收站，可恢复

### F05 联系人

对齐 `style-02`。Tab：全部 \| 常用 \| 有差额 \| 已停用。

**能力**：拼音搜、筛选、新建、编辑、停用、**合并同名**、个人明细。

**验收**

- [ ] 合并后流水迁移；停用默认不出现在记一笔搜索

**规则（锁定）**：`balance > 0`。

**操作**：视为已还 / 取消；「记还礼」预填抽屉；展示 **回礼建议额**（F20，可关）。

**验收**

- [ ] 与摘要/统计「待还」人数一致

### F13 统计页（v1）★

**入口**：左栏「统计」。

**筛选**：年份（默认今年）、成员、关系标签。

**摘要卡**：今年收礼合计、送礼合计、净额、往来笔数、当前待还人数。

**图表**（Recharts/ECharts 等 2D；**禁止 Three.js**）：

1. 收礼 vs 送礼（按月或年对比柱）
2. 月度净额折线/面积
3. 按关系标签收支占比（环图；空态友好）

**其它**：可切换「数据表」看聚合行；色觉友好（不只靠红绿）。

**验收**

- [ ] 切换筛选后图与卡一致
- [ ] 与往来同年筛选汇总误差为 0
- [ ] date 索引下大数据量可接受
- [ ] 含 F14 入口按钮

### F14 年度人情报告（v1）★

**入口**：统计页「生成 YYYY 年人情报告」。

**输出**：应用内多页预览 + 导出/打印 PDF。

**固定章节**

1. 封面：礼金簿、账本名、年份、生成日（公历+农历旁注）
2. 总览：收 / 支 / 净 / 笔数
3. Top5：收礼最多、送礼最多、净差额（待还向）联系人
4. 事由/节日分布简表
5. 待还摘要（人数、合计差额；不含已视为已还）
6. 页脚：个人备忘声明

**验收**：无数据空态不崩；金额千分位；视觉服从 `#0D9488`，无花哨插画抢数。

---

### F15 拼音 / 首字母搜索（P0）

- 联系人列表、记一笔联系人输入、⌘K 全局搜支持：汉字、全拼、首字母（如 `zs`→张三）。
- 联系人保存/改名时更新 `name_pinyin` / `name_initials`。
- **验收**：样例「张三」可用 `zhangsan`、`zs`、`张` 命中；大小写不敏感。

---

### F16 同名防重（P0）

- 新建联系人或记一笔「新建」时，若同账本存在相同 `name`（未停用、未删除），弹提示：选择已有 / 仍要新建 / 去合并。
- **验收**：无法在无提示下静默创建第二个「张三」。

---

### F17 回收站（P0）

- 删除流水/联系人（无未迁移流水策略按产品：联系人有流水则先提示）→ `deleted_at`；回收站可 **恢复** 或 **永久删除**。
- 可配置保留天数；到期可在启动时清理（或手动清空）。
- **验收**：恢复后列表与余额正确；永久删除不可恢复（二次确认）。

---

### F18 批量粘贴解析（P1）

- 入口：往来「批量录入」或顶栏菜单；多行文本框。
- 支持行格式示例（实现时文档化 2–3 种）：
  - `张三 800`
  - `李四 500 结婚`
  - `王五 收礼 1000 满月`
- 解析预览表：联系人（新建/已有）、方向默认（可改）、金额、事由；确认后批量写入。
- **验收**：20 行样例预览无错；部分坏行标红可跳过。

---

### F19 支付方式 + 礼品字段（P1）

- 记一笔与编辑：支付方式枚举；礼品可选填。
- 往来表可显示/筛选支付方式；CSV 导入导出含列。
- **验收**：旧数据字段为空不报错；筛选可用。

---

### F20 打印增强 + 回礼建议（P2）

- 打印金额旁或独立列：**中文大写**（人民币大写规则，单测覆盖常见金额）。
- 第 4 套模板：**竖排传统礼簿**（可选；现代三模板仍在）。
- 待还：「建议回礼」展示与一键填入；设置可关。
- **验收**：大写与数字一致；竖排模板可打印；关闭建议后 UI 不展示。

## 12. 附录 · CSV 列建议（导入导出）

`date,direction,amount,contact_name,relation,member,event,festival,payment_method,gift_note,note`

- `direction`: `in` \| `out` 或 `收礼` \| `送礼`
